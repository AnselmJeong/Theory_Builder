# v0.2 제품·동작 점검

기준: [GPUI Kit Design Guides](https://gpui-kit.com/docs/design-guides/).

주 작업은 연구 폴더를 열고 질문을 입력해 근거가 연결된 답변을 검토하는 것이다. UI는 `Workspace`가 표시 상태를 소유하고 서비스 actor가 저장·실행을 소유한다. 표준 Sidebar, Button, Textarea, TextView, resizable pane을 조합한다. ⌘Enter 실행, ⌘N 새 질문, ⌘, 설정과 native 메뉴를 유지한다.

## 발견 → 수정

- 선택적 `replaces_id`가 Codex strict schema의 required에서 누락 → 모든 객체 속성 required + null 허용 유지.
- `severity`는 임의 문자열 스키마였지만 low/medium/high만 검증 → 스키마에도 같은 enum 지정.
- 종합 문맥이 직접 선행 작업만 포함 → 전이 선행 작업과 ID를 포함, 독립 후보 격리는 유지.
- 실패를 근거 부족으로 표시 → 실행 실패·부분 답변·연구상 근거 부족을 구분.
- 버튼이 비활성인데 진행 정보를 찾기 어려움 → 입력창 바로 위의 지속적인 상태·시간·중단·상세 기록.
- 과도한 모델 버튼과 기술 설정 → 모델 선택을 줄바꿈 행에 모으고 CLI 경로는 고급 설정으로 이동.
- Claude에 인증 성공 표시가 약함 → 구독 인증 상태, 모델 별칭, 실제 응답 테스트, 사용량 정보 분리.
- 앱 내부 프로젝트와 ScholarPen 자료 분리 → 같은 프로젝트 폴더 사용, 자동 자료 동기화와 이전 원문 보존.
- 고정된 연구 관점 → 목적·관점·제약 자유 입력.
- 자료가 없으면 외부 근거 수집 불가 → 기본 문헌 검색, PubMed 초록 + TinyFish 검색/페이지 읽기.

## 검증 관점

주된 실행과 결과는 중앙 읽기 영역에 두고, 분석의 내부 JSON은 별도 검토 패널로 보낸다. 상태는 색에만 의존하지 않는다. 긴 문서는 읽기 폭을 제한하고, 자료·기록은 각 영역에서 스크롤한다. 단위는 테마와 rem 스케일을 사용하고 native 창 크기·분할 경계만 창 geometry를 사용한다.

현재 한계: 전체 라이브러리 의미 검색이 아닌 어휘 기반 발췌, OCR 없음, DOCX 각주·도형·수식 제외, EPUB/PDF 추출 크기 제한, 검색 결과의 관련성·논문 질은 모델의 비판과 사용자의 원문 검토가 필요하다. 모든 창 크기·배율·IME 조합을 검사했다는 의미는 아니다.
